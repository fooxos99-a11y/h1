# تحديثات الويب للتطبيق — Capawesome + Cloudflare R2

المشروع React/Vite مع Capacitor 8، وليس Next.js. ناتج الويب الأصلي هو `dist/madarij-mobile`، ولا يستخدم `server.url`. هذا التكامل يستخدم الإضافة المفتوحة المصدر مباشرة دون حساب Capawesome Cloud.

## حالة التفعيل

الكود ومسار GitHub جاهزان للإعداد. غياب `OTA_BASE_URL` و`OTA_PUBLIC_KEY` يبقي OTA معطلًا مع استمرار عمل التطبيق. لا توجد وجهة R2 أو أسرار حقيقية داخل المستودع. لا تجعل `OTA_ENABLED=true` قبل اختبار الإصدار الأصلي الجديد على iOS وAndroid. المزامنة والبناء المحليان لا يثبتان نشر التطبيق أو نجاح الاختبار على جهاز.

عند طلب النشر، تسجل وجهة R2 والنطاق والبكت وأسماء متغيرات الأسرار وطريقة النشر في `data1.yml` حسب AGENTS. لا يوضع أي سر فيه أو في Git. إعداد الوجهة ورفع النسخ الأصلية إجراءان مستقلان عن تجهيز هذا الكود.

## ملفات التنفيذ والمكتبات

- `package.json` و`package-lock.json`: تثبيت `@capawesome/capacitor-live-update@8.4.4` واعتماد التطوير `archiver@8.0.0` لتجهيز ZIP. إعادة استخدام `@aws-sdk/client-s3` الموجود أصلًا للرفع إلى R2.
- `capacitor.config.json` و`vite.config.js`: إعداد الرجوع الآمن وبيانات بصمة البناء؛ لم تُضَف `server.url` ولم تتغير الهوية أو الصلاحيات.
- `scripts/ota/config.mjs` و`sync-native.mjs`: حساب بصمة التوافق وإدخالها مع المفتاح العام في إعداد النسخة الأصلية أثناء المزامنة ثم استعادة ملف المصدر. لذلك تمر أوامر native الحالية عبر هذا الغلاف مع الحفاظ على حذف ملفات APK من الحزمة.
- `scripts/ota/keys.mjs` و`release.mjs` و`publish.mjs`: توليد المفاتيح والتوقيع والتجهيز والرفع والإيقاف والرجوع.
- `src/lib/otaProtocol.js` و`nativeOta.js` و`src/services/otaUpdateService.js`: التحقق والفحص والتنزيل وتأجيل التطبيق؛ الربط في `src/main.jsx` و`src/components/AppErrorBoundary.jsx` لمنع اعتماد شاشة خطأ كتحديث سليم.
- `.github/workflows/ota-updates.yml`: سير جديد للنشر بعد الفحوص؛ `.github/workflows/ios-testflight.yml`: تمرير رابط OTA والمفتاح العام لبناء iOS.
- إعدادات ربط Android و`ios/App/CapApp-SPM/Package.swift` ناتجة عن Capacitor sync. إضافة بصمات اعتماديات Android وتثبيت Alamofire في ملفَي `Package.resolved` على iOS مع إبقاء التحقق الأمني السابق.
- `tests/otaUpdates.test.js` و`tests/otaReadiness.browser.mjs` واختبار الاعتماديات الأصلي: فحوص الأمان والتوافق والرجوع وجاهزية الواجهة.

## الإعداد لأول مرة

1. أنشئ بكت R2 مستقلًا لهذا التطبيق واربطه بنطاق HTTPS مخصص. لا تستخدم `r2.dev` للإنتاج. جذر النطاق يعرض جذر البكت؛ لا تضع بيانات خاصة في البكت العام. امنع التخزين المؤقت لمسارات `channels/*`، ولا تضف Cache Rule تتجاوز `Cache-Control: no-store`.
2. اسمح بطلبات CORS من `https://localhost` و`capacitor://localhost` فقط، وبـGET وHEAD، دون cookies. مثال إعداد R2:

   ```json
   [{
     "AllowedOrigins": ["https://localhost", "capacitor://localhost"],
     "AllowedMethods": ["GET", "HEAD"],
     "AllowedHeaders": ["*"],
     "ExposeHeaders": ["ETag", "Content-Length"],
     "MaxAgeSeconds": 3600
   }]
   ```

3. أنشئ R2 API Token بصلاحية Object Read & Write لهذا البكت فقط. لا يحتاج التطبيق نفسه أي مفتاح R2.
4. شغّل `npm run ota:keys` مرة واحدة. ينتج مفتاحين في `.signing/ota/` المستبعد من Git. احتفظ بنسخة آمنة؛ فقدان المفتاح الخاص يتطلب إصدار متجر بمفتاح عام جديد. الأمر يرفض استبدال مفتاح موجود.
5. أضف GitHub Secrets وVariables أدناه. لا ترسل المفتاح الخاص في المحادثة أو تضعه في متغير يبدأ بـ`VITE_`.
6. للبناء المحلي، مرّر نفس إعدادات API و`OTA_BASE_URL` و`OTA_PUBLIC_KEY` المستخدمة في GitHub عبر متغيرات البيئة أو `.env.mobile` المستبعد من Git. اسمح بقيمة PEM متعددة الأسطر أو أسطر `\n`. رابط OTA للتنزيل فقط؛ لا يفتح الموقع داخل WebView.
7. شغّل `npm run verify` ثم `npm run native:android` و`npm run native:ios`. أمر iOS الأخير يحضّر الملفات فقط؛ البناء والتوقيع الفعليان يحتاجان macOS/Xcode. سير TestFlight الحالي يأخذ متغيرَي OTA الجديدين أيضًا.
8. سجّل قيمة `OTA native runtime` التي يطبعها أمر المزامنة. يجب أن تطابق قيمة `runtime` في `dist/madarij-mobile/ota-build.json` وفي بناء المنصتين. اختبر نسختي المتجر الأصليتين أولًا، ثم ضع البصمة في `OTA_NATIVE_RUNTIME`. زد أرقام إصدارات/بناء المتجر وفق مسار الإصدار الحالي؛ الإضافة Native وتحتاج إصدار متجر أولي.
9. اختبر OTA على أجهزة الاختبار، ثم فعّل `OTA_ENABLED=true` للنشر التلقائي من `main`. هذه القناة تشمل كل الأجهزة المتوافقة؛ لا توجد نسبة توزيع تدريجية في هذا التنفيذ الأول. لا تفعّلها قبل اختبار الأجهزة.

## GitHub Secrets

| الاسم | القيمة |
|---|---|
| `OTA_SIGNING_PRIVATE_KEY` | محتوى `.signing/ota/private.pem`، ولا يُضمَّن في التطبيق |
| `OTA_R2_ACCESS_KEY_ID` | Access Key ID الخاص بـR2 |
| `OTA_R2_SECRET_ACCESS_KEY` | Secret Access Key الخاص بـR2 |

## GitHub Variables

| الاسم | القيمة |
|---|---|
| `OTA_BASE_URL` | أصل HTTPS العام لبكت التطبيق، دون `/` أخير |
| `OTA_PUBLIC_KEY` | محتوى `.signing/ota/public.pem`؛ مفتاح عام غير حساس |
| `OTA_R2_ACCOUNT_ID` | معرف حساب Cloudflare |
| `OTA_R2_BUCKET` | اسم البكت المستقل |
| `OTA_NATIVE_RUNTIME` | بصمة آخر بناء أصلي مختبَر، وليست قيمة تُحدّث تلقائيًا عند كل push |
| `OTA_ENABLED` | `true` لتفعيل النشر التلقائي؛ اتركه فارغًا حتى اكتمال الاختبار |
| `MOBILE_API_BASE` و`MOBILE_API_ROOT` | إعدادات API الحالية نفسها المستخدمة في إصدار المتجر |

## طريقة العمل

- بعد ظهور شاشة فعلية واستقرار العرض 1.5 ثانية دون خطأ بدء تشغيل، يستدعي التطبيق `LiveUpdate.ready()`.
- يفحص ملف `channels/<runtime>/production.json` عند بدء التطبيق وبعد العودة إليه إذا مرّت 15 دقيقة. لا ينتظر تنزيل الحزمة لعرض التطبيق.
- يتحقق من توقيع بيان الإصدار واسم التطبيق وبصمة البيئة الأصلية والمسار والتسلسل الزمني. يتحقق المكوّن الأصلي من SHA-256 وتوقيع ZIP قبل استخدامه.
- التحديث إلزامي عند التشغيل البارد: تبقى شاشة التحميل الحالية ظاهرة ويُمنع التفاعل حتى انتهاء الفحص. عند وجود حزمة متوافقة وموثوقة، ينزّلها ثم يستدعي `reload()` لتطبيقها قبل الاستخدام، دون خيار تأجيل. بعد تشغيل الحزمة الحالية لا يعيد تحميلها في حلقة.
- فحوص العودة من الخلفية تُنزّل الحزمة وتجهّزها للتشغيل البارد التالي دون مقاطعة النماذج أثناء الجلسة. عند انقطاع الإنترنت أو فشل التوقيع/التنزيل يسمح بالنسخة الحالية؛ الإلزام ليس حظرًا للتطبيق دون إنترنت. الإضافة لا تضمن استمرار التنزيل بعد قتل التطبيق من النظام.
- عند فشل الشبكة أو التنزيل أو التوقيع تبقى النسخة الحالية. عند فشل بدء الحزمة خلال 30 ثانية تعيد الإضافة **نسخة الويب المضمّنة في إصدار المتجر**، وتحظر الحزمة الفاشلة بعد الرجوع؛ ليست آلية كشف لكل خلل منطقي لاحق.
- يستخدم GitHub `npm ci --ignore-scripts` ثم `npm run verify` ثم بناء الويب للجوال، وبعد النجاح يرفع ZIP والبيانات الموقعة، ويتحقق من الوصول العام للحزمة، ثم يغيّر مؤشر القناة. فشل الاختبارات أو البناء أو مطابقة البصمة يمنع النشر.
- الملفات الأصلية وإعدادات Capacitor والأيقونات وخلفية المهام وملف قفل الاعتماديات وإعدادات API ومفتاح التوقيع تدخل في البصمة. تغيير أي منها يتطلب إصدار متجر واعتماد بصمة جديدة. إدخال ملف القفل كله مقصود للتحفظ؛ حتى تحديث اعتماد ويب قد يتطلب إعادة اعتماد إصدار أصلي.
- عند تغيير Native، تستمر الأجهزة القديمة في قناتها السابقة. لا تحذف حزمها أو تعِد توجيهها إلى بصمة جديدة. يمكن استخدام نسخة مصدر الإصدار القديم محليًا لصيانة قناته عند الحاجة.

## النشر اليدوي

من GitHub → Actions → **OTA web updates** → Run workflow، اختر `main` ثم `publish`. ينفذ الاختبارات والبناء أولًا. أو محليًا بعد توفير المتغيرات في البيئة:

```sh
npm run ota:publish
```

يظهر معرف الحزمة SHA-256 في السجل، وتحفظ بياناتها تحت `releases/<runtime>/<bundleId>.json` للرجوع. النشر المحلي يحتاج `VITE_API_BASE` و`VITE_API_BASE_URL` بدل اسمي Variables الخاصين بـGitHub.

## إيقاف التحديثات مؤقتًا

1. اجعل `OTA_ENABLED=false` لإيقاف النشر التلقائي الجديد.
2. شغّل workflow يدويًا مع `action=pause`، أو `npm run ota:pause` محليًا.

تعطيل GitHub وحده لا يلغي حزمة منشورة. بيان pause يمنع التنزيل الجديد ويلغي الحزمة المنتظرة عند وصوله إلى جهاز يعمل. جهاز أغلق التطبيق بالفعل قد يطبّق حزمة سبق تنزيلها قبل وصول أمر الإيقاف؛ الإيقاف لا يسحب تحديثًا مطبّقًا ولا يعمل على جهاز غير متصل. للاستئناف انشر حزمة أو أعد توجيه القناة لحزمة سابقة.

## الرجوع إلى نسخة سابقة

- شغّل workflow مع `action=rollback` و`bundle_id` يساوي معرف حزمة ناجحة سابقة من **نفس البصمة**.
- استخدم `builtin` للرجوع إلى الملفات المضمّنة في إصدار المتجر.
- محليًا: ضع المعرف في متغير البيئة `OTA_BUNDLE_ID` ثم شغّل `npm run ota:rollback`.

الرجوع يطبّق مباشرة أثناء بدء التشغيل المحمي، أو يُجدول للتشغيل التالي عند فحص العودة من الخلفية، ولا يغيّر بيانات الحساب أو SQLite أو قاعدة الخادم. لا تُعد نشر حزمة محظورة بعد فشلها؛ أصلحها لتنتج معرفًا جديدًا. أبقِ API والبيانات متوافقة مع نسخة المتجر والحزم التي قد يرجع إليها المستخدم.

## ما يحتاج المتجر

إضافة أو تغيير Capacitor Plugins، Swift/Kotlin/Java، الصلاحيات وملفات Manifest/Info.plist، Bundle ID/Package Name، أيقونات وSplash أصلية، إعدادات Capacitor، مفاتيح الثقة أو نطاق OTA المثبت في التطبيق، وتغييرات لا تسمح سياسات المتاجر بإيصالها عبر OTA. كود الخادم وقاعدة بياناته لا يدخلان في ZIP الويب ويحتاجان مسار نشر مستقلًا.

## تحقق الأجهزة قبل التفعيل

اختبر على iOS وAndroid كلًا على حدة: فتح التطبيق دون إنترنت؛ تحديث صحيح؛ انقطاع التنزيل؛ توقيع خاطئ؛ حزمة ذات بصمة مختلفة؛ حزمة اختبار تتعطل قبل readiness للتأكد من الرجوع إلى نسخة المتجر وعدم تكرارها؛ pause وrollback؛ وبقاء جلسة الدخول ومسودات SQLite بعد التبديل. نجاح اختبارات JavaScript أو مزامنة Capacitor وحده لا يثبت هذه الحالات على الأجهزة.
